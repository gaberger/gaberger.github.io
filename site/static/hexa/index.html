Why it exists

Generating code stopped being the bottleneck. Checking it didn't.

An AI agent can ship a feature whose tests pass and whose shape is wrong: a use case that imports a database driver, a domain type that depends on an HTTP client. The suite stays green.

Tests answer does it run. Nothing answers is it still the system I designed. hexa adds that second question, as a gate.

01

A floor you can reproduce

A scaffold you can't reproduce isn't a foundation, it's a draft. The floor gate runs first because a skeleton that won't build makes everything after it meaningless.

02

Commits only on exit 0

hexa edits, runs your command, and commits only if it passes. Otherwise the edit reverts. A model that wanders commits nothing.

03

Rules travel with the project

Every scaffold ships .hexa/ADR-rules.toml. It's the contract the project keeps being graded against, not a starting point you leave behind.

04

The loop is recorded

.hexa/loop.json keeps each session's decision, gate and evidence. Hooks read it, and feature-sized edits with no gate are stopped.

Specs that can fail

A decision becomes sealed tests before any code exists.

The scenarios come from the decision record and its ports, never the code. A person signs off on what "correct" means, and no agent commit may edit the tests.

Quick start

Install once. Every verb is gated.

The script installs one binary from the latest release. Then hexa bootstrap sets up prerequisites, the inference server and config, and hexa self-update keeps it current.

# the floor alone: deterministic, runnable
$ hexa init ./myapp --scaffold --lang rust

# the floor plus what you described,
# gated on the build AND the grade
$ hexa scaffold "A bookmark service: SQLite store, HTTP API, tag search" \
    --target ./myapp --lang rust --grade A

Floor first, then the model

The skeleton must pass its own gate before any model is called.

Then two designs, two critiques, a build, a gate re-run, and a grade that must meet your floor.

$ hexa do run "make add() return a + b, not a - b" \
    --file src/lib.rs \
    --evidence "cargo test --test add"

Commits only on exit 0

hexa edits the file, runs the command, and commits only if it exits 0. Otherwise the edit reverts.

$ hexa analyze .                        # grade + rule violations
$ hexa analyze . --grade A              # fail below A
$ hexa analyze . --grade A --exit-code  # and on any violation
$ hexa graph consumers <path>           # who depends on this

Use the last flag in CI

--grade is a letter floor, so one violation can still grade A. Add --exit-code to fail on any violation.

# adversarial: hunt by lens, verify each finding, fix under the gate
$ hexa harden src/domain/merge.rs --gate "cargo test -p mycrate"

# cooperative: diverge, red-team, synthesize, build to the gate
$ hexa build "a bounded work queue" --target src/queue --gate "cargo test"

# either one, past any terminal or tool timeout
$ hexa harden src/ --gate "cargo test" --detach

Honest about who reviewed

Each pass names which reviewer answered. If none did (a spend limit, an expired login), it says nothing was reviewed instead of reporting a clean file.

$ hexa loop adr ADR-2609131800               # the decision
$ hexa loop gate "cargo test --test add"      # before the code
$ hexa loop evidence "cargo test -- --nocapture"
$ hexa loop stage done                       # evidence into the ADR
$ hexa loop                                  # every session's state
$ hexa spend                                 # tokens and dollars

The number is the tree's number

stage done writes the evidence command's own output into the ADR, with the commit it ran at. A failing command writes nothing and refuses to close.

$ hexa doctor      # non-zero when a check fails
$ hexa go          # the next right thing
$ hexa --version   # the commit it was built from

Checks, doesn't echo

doctor resolves every configured model tier against the backends it can actually reach, so a tier nothing serves fails.

Why hexagonal

Because its rules can be checked by a machine.

"Good separation of concerns" can't be graded. Dependencies pointing inward can. hexa analyze walks the AST of every file to check these six rules. Hover one to see its layer.

1domain/ imports only domain/
2ports/ imports domain/ only
3usecases/ imports domain/ and ports/ only
4Adapters import ports/, never the domain directly. A primary adapter may also call usecases/.
5Adapters never import other adapters.
6Only a composition root imports an adapter.

Rule 4 is the one that breaks. Ports re-export the domain types adapters need, so each adapter has one edge into the core and swapping a database touches one file.

The agent loop

A model that wanders commits nothing.

One loop, in process. It gets graph context and ranked lessons, reads and checks with a short list of guarded tools (no arbitrary shell), and proposes one edit. Your evidence command decides.

A pass that exercised nothing is rejected. A failed edit reverts atomically. With several models configured, the first edit that passes wins.

Why Rust, Go and TypeScript

Each has a compiler, and a compiler is a gate.

A wrong shape fails in seconds, before any test runs. And the grade needs imports that are explicit at build time; duck typing and runtime loading hide the boundaries.

Rust

Strictest. crate::, super::, inline paths and paths inside macros are all read.

Go

Module paths from go.mod decide what's inside the project.

TypeScript

Most forgiving. tsconfig aliases, require() and import() are graded.

Strictness makes the gate stronger and the task harder: weaker models fail Rust and Go where they pass TypeScript. A gate a model can't pass is doing its job.

Limits

What it doesn't do yet.

Kept on the page on purpose.

Finding a bug from a failing test

Given a rule, hexa finds every file that breaks it. Given only a failing test name, it found the right file once in ten.

No "refactor to a grade" verb

The refactoring trial ran through hexa build with the analyzer as its gate. It worked; it isn't a verb yet.

What a static import can't show

Code a macro generates from an allowed crate, reflection, and FFI. Modules named at run time get a warning, not a pass.

It doesn't write the code

A frontier model does. hexa adds the floor, the gates, the grade and the adversary: it makes a capable model disciplined.
